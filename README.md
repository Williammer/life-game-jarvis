# Jarvis · 成长总览与模块路线原型

沿用 C 证据工坊 + A 差距图。跑步、Agent 实践、陪伴与新增模块使用同一套结构：现状与证据、近期任务、中长期路线、榜样及可比 gap。由 Jarvis 提出目标和评估，用户补充背景、讨论并确认。

```sh
cd /tmp/jarvis-module-atlas
python3 serve.py
```

打开 http://127.0.0.1:5180/ 。无新增依赖，状态仅在内存中，刷新清空。手机可在可信局域网用 `python3 serve.py --bind 0.0.0.0`，访问电脑 IP 的 5180 端口；默认仅本机访问。

## 建议试玩

1. 从「成长总览」比较三个模块的现状、任务、规划与榜样 gap。现状分是模块内的目标达成度，不能跨模块解释为能力排名；行动 XP 单列。
2. 在跑步模块点「与 Jarvis 分析」，查看建议目标、量化依据、未知项和阶段路线。点 Gary，比较新的参照提案；「确认采用」后更新 gap 和路线。
3. 在讨论中输入「现状：规律活动3次，恢复观察4次，请分析目标与gap」。观察资料如何进入评估提案；确认前原有现状不变。
4. 打开 Agent 实践，查看四项作品验收及近期任务。点「放入今日草案」，确认入历后选中任务，用对话记录完成情况。自述只累积行动 XP；展开记录，点「模拟通过能力验收」才更新对应能力分项。
5. 新增「英语口语：希望能独立做一次英文技术分享」。新模块复用总览、详情、日历和证据记录；背景不足时显示待评估。可补充公开榜样来源，原型将保留待核查状态。
6. 手机详情通过「模块与路线 / 与 Jarvis 讨论」切换。管理区支持暂停、恢复；可说「重命名为…」。更改模块或日历后，旧评估需要重新分析。

原有日历支持描述安排、编辑时间块、确认草案、部分完成和临时打断。旧预览保留：[今日工作台 5179](http://127.0.0.1:5179/) · [三套比较 5178](http://127.0.0.1:5178/) · [本服务内比较页](http://127.0.0.1:5180/variants.html?variant=C&step=1)。

## 从原型到正式 Agent 的约定

模块由数据定义，共享渲染和日历，不为每个方向复制一套页面。共同对象包括模块意愿、现状指标与证据、目标及量表、榜样来源、差距评估、分阶段路线、任务引用、版本与变更记录。

正式分析链路：已确认的个人背景 + 当次观察 + 领域来源 → Jarvis 判断哪些维度可比，提出阶段目标、指标/权重、gap 与路线，列出依据和缺失信息 → 用户讨论确认 → 按已确认口径确定性计算，保存来源及版本。新证据改变判断时提出修订；未知不自动记为零，目标改变不能无痕改写历史。用户无需自行制定量表。

目标、0–100 展示方式、权重和规划窗口都是演示假设，尚未冻结评分算法。实际成绩差使用同定义数据；作品清单反映约定的验收覆盖，不代表掌握某位专家百分之多少。Road to match 是分阶段行动路线，不是追平期限保证。游戏 XP、能力证据与现实成绩分开。

## 当前边界

这是可抛弃的本地规则模拟，**没有真实 LLM 推理、即时研究、Agent Native runtime 或 Google Calendar 接入**。人物/作品引用有公开来源；个人背景、评分、任务时长和验收均为虚拟数据。未知榜样链接只保存，不读取或假装核验。

本地对话只覆盖示例语法：现状观察需要使用页面上的准确指标名，分析使用预置案例；不能据此判断模型推荐质量。新模块先建立待评估基线任务，不凭名称生成专业训练处方。晨间约三分钟、长期动力及评分公平性仍需本人试玩和后续验证。
