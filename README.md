# Jarvis · 15 个交互原型

五个环节各三种方案，组成三条完整的游戏体验。资产保存在可抛弃分支 `prototype/jarvis-game-lab`，尚未选为生产设计。个人资料、Agent 建议、核验与评分都是演示，真实榜样链接可核查。

```sh
cd /tmp/jarvis-game-lab
python3 serve.py
```

打开 http://127.0.0.1:5178/ 。无需安装依赖。Node 22+ 可运行 `node check.mjs` 验证核心模拟规则。

手机试玩：在可信的同一局域网运行 `python3 serve.py --bind 0.0.0.0`，用手机访问电脑的局域网 IP 加端口 `5178`。默认只监听本机。

## 建议试玩顺序

1. 先走完 B：查看真实参照 → 晨间填时间与精力 → 选牌 → 确认。
2. 执行时模拟一次中断，观察确认前后当前计划是否变化。
3. 展开任务，填入示例证据；先保存“部分完成”，再改成完成。重复保存，核对 XP 没有翻倍。
4. 到结算页检查行动 XP、能力证据和独立测量三种变化。体验缺少能力证据时不会解锁。
5. 保留同一进度，底部切换 A / C；每个环节可记下偏好并导出文本。刷新会清空。

页面底部的“原型试玩工具”提供五个场景：普通日、低精力、临时被打断、缺少能力证据、结算样例。直接进入执行或结算且没有计划时，明确提示先确认或载入样例。

## 本轮取舍

- A 验证路线与长期成长是否更有吸引力；B 验证资源取舍是否更快；C 验证证据结算是否更可信、记录负担是否可接受。
- XP、优先分、精力格和解锁门槛均为待校准游戏规则，不是科学 ROI 或健康量表。
- 修改必做事项与愿望只保留文字；模拟器不理解任意自然语言、不自动解日历冲突。采用任务顺序和总预算，不做分钟级日历排程。后续 MVP 用 Agent 对话补齐这一段。
- “模拟核验通过”是试玩开关，没有执行代码、验证文件或判断实际健康状态。原型不调用 LLM、不导入个人记录、不持久化、不购买奖励。
- 当前仅实现四项 AI 能力的有限节点；跑步用同距离成绩作描述性差值；育儿评价自己的投入。不存在跨模块“人生总能力分”。
- 前端无外部依赖。生产实现继续按既有研究验证 BuilderIO agent-native 与 Apace 控件、路由、样式和检查配置，本分支不会直接成为生产代码。
