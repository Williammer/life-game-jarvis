# Jarvis · AI-native 个人成长远征

升级自 `prototype/module-atlas`，保留今日与成长总览、直接编辑日历、讨论提案、确认后生效，以及统一的生活模块。

```sh
cd /tmp/jarvis-ai-native
python3 serve.py
```

打开 http://127.0.0.1:5180/ 。无新增运行依赖，默认只监听本机。状态在内存中，刷新清空。所有初始个人数据均为虚构样例。

## 建议试玩

1. **今日选择**：看顾问用了哪些背景，给 Agent 选择「最小一步 / 标准挑战 / 进阶尝试」。恢复与陪伴也有可选择的产物；不会把进阶简单解释为更大运动量。
2. **确认合约**：写一个开始锚点，点「生成今日任务提案」。比较当前日历与草案、分钟和精力，确认后才生效。标准组合为 75 / 90 分钟，留 15 分钟余量。
3. **行动与中断**：开始 Agent 挑战，只勾第一个检查点，写一句实际产物，记录 20 分钟；保存后获得 10 / 30 XP，能力不自动增长。营地复盘可生成减量草案。
4. **证据与解锁**：继续完成三个检查点，保存作品描述。在「今天留下了什么」展开记录，点「模拟通过能力验收」。成长总览中受控写入节点点亮，下一步变成失败用例；纯自述不能跳过前置。
5. **最小产物边界**：最小一步全完成并模拟核验，仍不会证明完整的受控写入能力；之后可以另确认标准挑战，XP 覆盖重算，旧检查点留在变更记录中。
6. **贴身上下文**：查看每条事实的范围、来源与日期，撤下不适用背景或补充最近经历。旧计划与模块分析因此过期。修正容量只生成待确认草案。
7. **跨领域成长**：健康显示同定义赛事差距及其限制；家庭缺基线保持未知，只奖励本人可控行动。新增模块复用同一套路线、日历与证据，不凭名称补分。
8. **就地协商**：在榜样、gap、目标、每个阶段、挑战标准、背景、检查点和复盘旁点「与 Jarvis 讨论」。试“改用 Gary”“马拉松成绩改为 4:10:00”“近期改为先做只读提案”，接着“验收改为留下失败观察”。看局部前后差异，继续修改或拒绝；确认后更新原对象。每处保存自己的草稿与对话，可撤销当前版本内的修订。
9. **成长纪念**：本轮 60 行动 XP + 一项完整能力模拟验收，选择并领取一次演示纪念。不会购买或消费。

## 依据与实现边界

- [四本游戏设计经典与论文的研究](docs/ai-native-gamification.md)：明确选择性章节阅读、原始论文获取范围、设计推导与证据限制。
- [AI-native 应用与反馈协商研究](docs/ai-native-feedback-design.md)：BuilderIO、混合主动交互论文、Microsoft Fluent 与 Linear 的一手证据；访问限制明确列出。
- [检查点反馈设计](docs/feedback-design.md)：覆盖矩阵、共享讨论面板与确认边界。
- [本轮设计与机制](docs/ai-native-design.md)：产品定位、结构、规则及验证重点。
- [验证记录](docs/verification-ai-native.md)：规则和浏览器检查、手机与键盘、限制。

主循环：个人上下文 → 榜样/作品差距 → 可选挑战合约 → 检查点与行动证据 → 顾问评估 → 能力关卡与下一轮。

这是 AI-native 交互与契约的本地模拟，**没有接真实 LLM、BuilderIO agent-native runtime、私人历史、外部日历或付费服务**。顾问使用可审查的预置领域分析与上下文引用，未执行即时研究；新增背景原文会进入依据，但不能据此声称已完成专业语义理解。XP 和 0–100 展示为演示设计，非科学人生评分。验收按钮不执行真实代码或健康测量。

正式版可沿用同一对象与动作边界接真实 Agent：检索已授权背景与专业来源 → 提出结构化可讨论方案 → 校验版本和规则 → 用户确认 → 保存证据 → 复核与下一步。原型不另建生产框架。
