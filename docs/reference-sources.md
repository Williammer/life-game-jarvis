# 榜样基础资料与领域评估

2026-10-03。用户可在成长总览的“补充榜样资料／设置榜样与资料”、领域详情或榜样讨论中打开资料编辑器。沿用已有榜样对象、领域上下文、两种评估模式与确认机制；没有新增依赖。

## 可以提供什么

- GitHub 个人主页与活动线索、LinkedIn、X / Twitter。
- 公开文章／论文、视频／演讲、代码／项目、其他公开成果。
- 每条资料的公开链接、可选标题，以及“这条资料能支持什么判断”的说明。
- 榜样名称、希望观察的时间范围、针对当前领域希望评估的能力和成果。

最多 12 条资料，可自动识别常见平台或手动指定类型。完整 HTTP(S) 地址、无登录信息、长度与重复地址均做校验。资料类型不代表其可信度；本人说明只是核查线索，不是已验证事实。

## 交互与数据边界

新增榜样与编辑现有榜样使用各自独立的草稿，并按模块隔离。添加／移除表单行、收起、输入错误和拒绝提案都不改变有效榜样。提交展示资料、领域、观察范围、未知项、评估与路线提案；确认后才更新。每条已采用来源都有独立反馈入口，可讨论、纠正链接或提出移除。

草稿基于模块版本；模块变化后未提交的草稿不能覆盖新事实，可明确重新载入当前版本。已提交且采用的资料重新打开时读取当前集合。来源修订复用已有版本守卫和撤销流程；行动 XP 与个人原始证据保留。

补充资料不会增加能力分。预置数量／清单参照保留其原有口径，新增资料仍是待读取。撤回原始参照链接或更换人物名称后，原分数不再借给新的来源，榜样与同口径差距恢复待评估。自选榜样不会因名字、链接、粉丝数或 GitHub 提交数而被默认为 10 分或渡劫。

## 正式 Agent 的评估依据

`analyzeModule` 将 `referenceBasis` 和 `referenceResearch` 放入现有分析提案。后者包括领域、个人目标、用户评估重点、观察范围、完整来源集合、当前模块维度，以及以下核查要求：

1. **身份与归属**：确认主页属于该榜样；区分本人贡献、团队成果、转发与 AI 辅助，核查发布时间、版本和可访问范围。
2. **领域相关性**：只评价当前领域的能力与成果；GitHub 活动反映持续性和协作线索，不能替代作品可靠性、技术判断或实际使用效果。
3. **交叉核验**：结合原始代码、测试、文章论证、公开视频和可复核成果。区分本人自述与外部证据；记录缺失、冲突与时效。LinkedIn／X 等需要登录或不可访问的内容保持未知。
4. **透明量表**：先讨论同口径维度与验收标准，再给分项评分；每个分项回链到实际原文／代码／成果，说明理由、可信度和缺失信息。没有证据的维度不给确定值。
5. **共同校准**：双方沿用相同标准，将结果映射到数量／分数或修炼境界。用户可纠正归属、证据和判断，重评形成新提案，确认后采用。只表示同领域、同口径表现，不做人格或跨领域排名。

真实 Agent 返回的每个评分分项应包含 `dimension`、`score`（可为空）、`rubric`、`sourceIds`、实际引用／定位、读取时间、可信度和缺失信息；汇总分、境界与差距从同一组获认可的分项推导。当前没有实现抓取、登录、第三方 API 或真实模型推理，资料状态不会伪装成“读取完成”。这轮预留并验证输入、分析上下文、证据边界和反馈闭环。
