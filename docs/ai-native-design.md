# Jarvis AI-native 游戏化升级设计

2026-10-02。可交互原型；假设与真实 AI 能力分开。实现继承 module-atlas，原比较页面保留。

## 产品问题与范围

个人上下文与专业依据应该改变今天选什么、如何开始、怎样判断进步，而不只在打勾后增加积分。仍只有今日与成长总览两个主入口。用户授权本轮直接升级原型；不读取私人历史、接付费模型或外部日历。

## 设计方向

颜色：云蓝 #f3f5fa、墨蓝 #202b48、靛紫 #5964d9、恢复绿 #277f72、家庭琥珀 #9a691c、白 #ffffff。
字体：系统中文无衬线，英文用系统 humanist sans；标题 32/24/20，正文 14/13，最小辅助文字 11。数值等宽。
结构：今日为顾问简报 → 主线与三个任务选择 → 日历 / 上下文对话 → 行动证据 / 营地复盘；成长为当前远征 → 三条领域路线 → 详情中的量化 gap、上下文、顾问和证据。

```
今日                              成长
个人状态 / 顾问简报                当前远征 / 下一个证据关卡
主线挑战  恢复支持  家庭连接        领域身份 | 证据节点路线 | 榜样差距
难度与产物 → 生成草案               点击节点 → 解释前置与任务
日历当前 / 草案 | Jarvis            现状与来源 | 专业顾问
开始 → 检查点 → 记录                下一步建议 → 入今日草案
```

审查：不做泛用仪表盘，不给跨领域能力总排名。视觉大胆点落在证据节点路线，周围操作保持克制。家庭路线用本人可控行动与关系观察；恢复与未知都有可读状态。

## 实施顺序与文件边界

- [x] `journey.js`：上下文样例、挑战合约、证据关卡、安排与完成评估；纯函数，所有规则可复算。
- [x] `day-model.js` / `model.js` / `module-model.js`：合约随提案确认生效；按检查点奖励；最小挑战不冒充全能力验收；已有版本和幂等检查继续适用。
- [x] `module-ui.js` / `day.js` / `journey.css` / `index.html`：今日任务选择、行动工作区、上下文修正、成长远征与顾问复盘；桌面/手机/键盘体验。
- [x] `check-journey.mjs`：检查证据关卡、检查点部分结算、重复记录、过期上下文提案、最小任务验收边界、未知与恢复。
- [x] 文档：书籍与论文研究（主仓库 `docs/research`）、本分支设计与验证、主仓库预览入口更新。

## 机制与边界

1. 主线来自榜样具体成果/作品验收项，阶段解锁来自证据，不由 XP 解锁健康权利。
2. 最小/标准/进阶有不同产物、分钟、精力与事前奖励预算；缩时不自动降低原验收条件。
3. 部分完成按已记录检查点占比结算；未知完成度允许保存观察。自述与模拟核验分别展示。重复提交替换同一记录，不叠加 XP。
4. 个人事实有来源、时间、范围和本次使用开关；补充背景让旧提案过期，确认后才改计划。
5. 营地复盘分别评价安排与行动，给出下一次可实施的提案。未记录不当成失败。恢复不制造积分债务。
6. 个人样例、规则分析与验收均标明模拟；正式版需要同一结构化契约接 BuilderIO agent-native，由真实上下文检索和专业来源支持。

## 验证重点

90 分钟内的标准组合；低精力减量；任务中断后保留部分证据；自述达标不解锁；模拟验收后开启下一阶段；最小挑战验收仍不证明整项能力；重复保存无重复奖励；旧日历与上下文提案无法确认；新增模块仍未知；来源/文本安全；390px 无横向溢出；键盘表单与 reduced-motion。

## 检查点协商升级

基于 [AI-native 反馈研究](ai-native-feedback-design.md)，由 `feedback.js` 提供同一对象的讨论描述、有限本地回复、修订／确认／撤销与共享原生 dialog。`day.js` 只保存各对象的线程、草稿与当前选择，并调用现有模块与日历动作。重要建议旁的常驻轻量入口不依赖 hover，手机与桌面共用；具体覆盖见 [反馈设计](feedback-design.md)。

修订携带背景、日历、模块与有效草案的版本。解释不改有效对象，能力不由共识认证；完整验收可以撤回为自述，行动 XP 保留。两轮修改的差异始终对比真实原对象。确认后同步主页面，当前版本内支持撤销。
