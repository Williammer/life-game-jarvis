# Jarvis：从经典游戏设计到 AI-native 个人成长机制

研究日期：2026-10-02。研究对象是当前 `http://127.0.0.1:5180/` 原型的「今日」和「成长总览」。本文提供本轮机制与体验的设计依据，继承 [领域依据与公平评分](/Users/he.william/Documents/tech/__dev/_pers/life-game-jarvis/docs/research/evidence-scoring.md)、[真实榜样参照](/Users/he.william/Documents/tech/__dev/_pers/life-game-jarvis/docs/research/reference-benchmarks.md) 和 [Agent Native 交互研究](/Users/he.william/Documents/tech/__dev/_pers/life-game-jarvis/docs/research/agent-native-interaction-patterns.md) 的边界。

**核心判断：Jarvis 最有价值的游戏不是“做任务换积分”，而是“和真正了解我的专业顾问一起，选择一条可行路线，产生真实证据，看见自己缩小了哪一块差距，再解锁下一种能力”。** AI 负责理解、专业分析和持续调整；游戏机制负责使选择有意义、使进步可感知、使困难日仍然能回来。今日是一次可调整的行动回合，成长总览是由真实证据逐渐展开的长期能力地图。[B1–B4][P1–P4]

## 2. 四本书共同指向的核心体验

### Schell：先决定用户感受到什么，再选择机制

Schell 区分游戏和游戏产生的体验，lens #1 要先明确核心体验；四大元素是机制、故事、美学和技术，需要互相支撑。[B1：第 2／4 章，PDF 43–44、61–63]

Jarvis 的核心体验可写成三个可验收的句子：

- **被理解：**“它知道我为什么做这件事、做到哪里、今天实际能投入多少，以及我为什么可能卡住。”
- **能够胜任：**“我知道这次怎样算有进展，遇到困难有可行的降档或提示，并能看见昨天不会的东西今天会了。”
- **掌握选择：**“顾问能提出专业判断和取舍，但目标、承诺和今天如何安排由我参与决定。”

主题建议采用“个人远征与顾问团”：学习、健康、家庭是同一个人的不同发展路线。叙事必须来自真实选择与证据，例如“第一次完成可复现评测”，而不是把一次点选编造为拯救世界。技术上，AI 的上下文理解应实际改变任务与判断；美学上，让路线、检查点、证据归档和能力解锁承担情感反馈。四元素共同服务这三个体验，才能使 AI 和游戏化都成为产品结构。[B1][P1]

Schell 还区分真实技能和虚拟技能：角色数值升级可以让人满足，但玩家本人是否变强是另一件事。[B1：第 10 章，PDF 159–160] **Jarvis 的角色等级可以庆祝持续行动，能力地图必须由个人证据支持。**

### Koster：有趣的不是重复奖励，而是仍有模式可以学会

Koster 将游戏乐趣与学习、理解模式、实践和掌握联系起来；太简单、太难、变化太慢或太快都会导致厌倦。其“游戏是老师”的判断是有用的设计视角，不等于所有快乐都只有一个生理原因。[B2：第 2／3 章，PDF 28–62]

因此“读 30 分钟文章，+20 XP”可以是投入记录，却不是完整的学习玩法。更深的 Agent 实践任务可以是：

1. 先预测一个失败案例属于检索、规划还是工具调用问题。
2. 跑一次固定评测，比较预测和结果。
3. 解释为什么失败，选一种改进，再测一次。
4. 由顾问指出新发现的模式；把同一能力应用到一个新问题。

真实未知和技能进步本身可以持续产生发现感。AI 应调整任务所需理解的层次，避免反复生成看似新颖、实际只是换措辞的签到任务。[B2][B4：10.3]

对跑步，这种模式学习可以是识别强度与体感、建立适合自己的恢复节奏；对家庭，是理解冲突触发、倾听与修复方式。不能因为家庭与健康不适合做谜题，就强行把它们变成答题或分数竞赛；对应的真实改善才是乐趣所依附的价值。

### Sylvester：机制产生事件，事件产生情感，情感形成体验

《体验引擎》的核心链条是：机制 → 被虚构层包装的事件 → 情感 → 体验。[B3：第 1 章，PDF 65–66] 对 Jarvis 而言：

| 机制／真实事件 | 希望引发的情感 | UI 中的可见反馈 |
| --- | --- | --- |
| 承认只完成一个关键检查点，保存失败日志 | 如释重负，努力没有消失 | 证据卡归档；“已完成基线，改进实验待续” |
| AI 从历史失败中指出可复现的原因 | 领悟，“它确实看懂了” | 前后证据对照，指出具体改变 |
| 选择适合当日状态的挑战档位 | 控制感，愿意开始 | 明确时间与验收条件，不贴懒惰标签 |
| 能力证据满足一个前置条件 | 成就与好奇 | 节点展开，新任务／工具方法可用 |
| 家庭临时事件后重新安排剩余一天 | 安全与被支持 | 显示保留事项、调整事项与取舍原因 |

其弹性挑战不是简单的“降低难度”，而是允许不同程度的成功，使不同水平都有可达而有挑战的目标。[B3：第 3 章，PDF 93–95] Jarvis 的任务应同时具有最低可保留进展、标准验收、可选延伸；健康任务的“延伸”仍须符合个人安全限制，不能默认等于加量。

其“奖励一致性”要求奖励所鼓励的行为接近用户本来就想做的行为；机械发奖可能把探索和创意变成以最小成本换分。[B3：第 8 章，PDF 237–241] AI 比传统规则更有机会识别作品、发现、反思和关系修复，但仍可能错判；不能因为有模型就声称已解决难以检测内在价值的问题。

### Adams／Dormans：真正的深度来自资源、反馈和进阶的关系

该书把机制定义为规则、流程与数据，分析内部经济中的来源、池、消耗和转换，并强调正反馈不必是有益的、负反馈不必是有害的。[B4：1.1、4.1、6.2.6] Jarvis 的重要资源不是虚构金币，而是有限的**时间、可投入精力、已有能力、可信证据和现实承诺**。

最有价值的三条相互作用的反馈：

- **能力正反馈：**行动产生证据 → 找到真正薄弱环节 → 更准确的练习 → 能够完成更复杂任务。奖励是新能力和新选择。
- **过载调节反馈：**排程过满／状态不足 → 缩小承诺、补恢复、改变方法 → 下次更容易执行。它纠正策略，不惩罚人格。
- **上下文学习反馈：**计划与实际产生偏差 → 分清耗时低估、技能障碍和外部打断 → 更新个人背景与预测 → 排程建议更贴近现实。用户可以更正错误归因。

不要建立“高分 → 更高倍数 → 更容易高分”的无限刷分正反馈，也不要建立“未完成 → 扣分 → 更难升级 → 更不愿回来”的失败陷阱。书中的锁与钥匙机制可用于能力前置：已经验证的技能是一把钥匙，解锁需要它的新挑战；健康和家庭的基本支持不应被 XP 锁住。[B3：PDF 99–101][B4：11.1]

| **奖励预测，Schultz／Dayan／Montague 1997** | 作者摘要讨论灵长类多巴胺神经元的输出与未来重要奖励预测变化／误差。[P8] | 使用“发现感、明确反馈、愿意回来”等可观察体验词；不做个人多巴胺计量 | XP／颜色／动效能定量增加多巴胺；随机奖励会让个人成长更好 |

Sailer／Homner 的学习场景元分析报告认知 `g = .49`、动机 `.36`、行为 `.25`，对应样本与置信区间分别不同；这些是标准化组间效应，**不是个人提升百分比**。其方法严格的子样本中动机与行为效应较不稳定，明确要求情境化理解。[P6，Abstract 与 Discussion] 对本产品，最可靠的态度是把机制做成可验证假说，观察是否让人更愿意完成有价值行动，以及真实证据是否改善。

用户说“充分多巴胺”可以理解为希望行动有期待、有满足、有动力。产品应据此提供成就、领悟和陪伴；不用伪科学的“多巴胺 +15”、抽奖或惩罚性 streak 实现这个目标。[B2][B3][P8]

## 4. AI-native：上下文不是聊天背景，而是每个机制的输入

Jarvis 需要形成一个可纠正的个人模型，而不是每次聊天重述职业、健康和家庭背景。实际储存机制可沿用现有工具，不要求在原型阶段搭建新平台。[既有：agent-memory.md]

### 分开四类信息

| 信息 | 例子 | 应如何表达 |
| --- | --- | --- |
| 事实与记录 | 某天的跑步记录、评测产物、日历承诺 | 来源、日期、采集方式、适用范围 |
| 用户目标与价值 | 更重视可持续健康、希望深入 Agent 评测、约定家庭时间 | 用户确认，允许修改和暂缓 |
| AI 推断 | 某类实验耗时常被低估、当前可能缺少基线比较能力 | 引用依据，标明是推断，保留替代解释 |
| 待确认信息 | 是否有伤痛、孩子年龄、已有作品能否复现 | “待补充／待评估”，不能默认为零或事实 |

“充分上下文”意味着对当前判断重要的信息足够充分，不意味着默认收集所有信息。每个顾问应能说明读取了哪些背景、哪些已过期、哪些缺失；家庭和孩子信息按需要最少保留，不以全程录音／聊天抓取交换专业感。

### 专业顾问不是不同名字的通用聊天机器人

- **Agent 实践顾问：**理解技术基线、最近作品、评测设置、使用了哪些模型与帮助；区分“复制可运行”“能够解释”“独立改进”“迁移到新问题”。建议包含方法、验收、失败处理与可复现性。
- **健康顾问：**理解目标、活动基线、恢复与限制、已有专业建议；把持续性与计划执行分开评估，不以更快更远作为唯一成长方向。
- **家庭顾问：**理解孩子阶段、家庭约定、照护负荷和用户的关系目标；关注用户自己的倾听、回应、协调与修复，不对孩子的表现给父亲发奖。
- **总协调 Jarvis：**处理时间与精力冲突，解释“这一天为什么这样排”，而不是把各领域的建议简单相加。健康恢复和重要家庭承诺可以改变今天的技术学习挑战。

跨领域协调不必让每个顾问读取全部敏感资料；例如学习顾问只需要“晚间不可用、今日可用精力较低”，未必需要孩子的冲突细节。建议依据的可见性是专业体验的一部分，也是防止模型自信地误解用户的机制。

### 每条重要建议的最小结构

**判断 → 引用的个人证据／领域依据 → 不确定或缺失 → 两个可行选项与成本 → 推荐的下一步 → 用户可修改的承诺。**

例：“上次实验只有改进版结果，缺固定基线，所以现在无法确认提升来自你的修改。今天可用 35 分钟，建议只跑固定基线与一个失败案例；如果想挑战，再比较一个修改。依据是实验记录 E17 和今天时间约束；缺评测脚本的运行记录，判断暂为待核验。”

这段对话必须能更新实际任务草案和验收条件。只在 UI 边缘放一句泛化建议，不构成 AI-native。

## 5. 两个页面应共用的四层循环

```mermaid
flowchart LR
    A[个人上下文与真实证据] --> B[领域顾问：榜样能力与差距]
    B --> C[用户选定近阶段目标]
    C --> D[今日：挑战合约与可调整安排]
    D --> E[执行与检查点]
    E --> F[完成记录与证据收据]
    F --> G[顾问评估：行动、能力、计划偏差]
    G --> H[成长：证据更新与下一能力解锁]
    H --> A
    G --> D
```

**长期循环：方向 → 榜样能力 → 差距 → 阶段作品。** 按一个月或一个章节组织，不强制固定赛季长度；“章节完成”意味着完成一组有意义的现实验收，不是刷够 XP。

**周循环：观察 → 调整路线 → 选择下周重点。** 顾问指出一个真实改善、一个主要瓶颈、一个可执行实验。恢复、家庭和探索也可成为本周重点。不能用总体分把某一个领域压成永久弱项。

**日循环：评估今天 → 选择挑战 → 安排 → 随变化改道 → 留证据 → 复盘。** 今日安排和成长地图共享同一项任务、同一份证据、同一验收规则，避免今日全绿、成长却没有变化。

**行动循环：预测 → 行动 → 反馈 → 反思／重试。** 一个长任务有一个最小检查点，失败能留下信息；提示深度可选，完成后显示具体收获。不要让用户为记录游戏而大量中断现实活动。

## 6. 今日：从任务清单变成由顾问支持的一回合

### 开场：今日局势与推荐挑战

主视图先显示今天最重要的背景变化、可用时间和当前主线；示例文案必须明确是演示资料。可显示三张简洁内容：

1. **今日局势：**已有承诺、可用窗口、精力自述与最近关键证据。
2. **顾问建议：**今天最值得推进哪一个缺口，为什么；其他领域保留哪些底线。
3. **本回合承诺：**用户实际选择的行动与验收，剩余可支配时间。

不要把每个模块都变成必须每天推进的日课。健康与家庭的某些事项适合规律安排，深度实验更可能需要完整时间块；协调应反映领域特性。

### 挑战合约：最低保留、标准验收、可选延伸

以演示 Agent 任务为例：

| 档位 | 行动与可见产物 | 意义 |
| --- | --- | --- |
| 最低保留 | 跑固定基线，保存一次结果与一个失败例子 | 今天即使被打断，也能留下可复用起点 |
| 标准验收 | 比较基线与一个修改，记录差异与解释 | 补上当前评测方法缺口 |
| 可选延伸 | 用新案例检验解释是否仍成立 | 探索迁移能力，不强制加时 |

每个档位都给时间估计、前提、验收条件、预期证据和奖励规则。不能只显示“简单／普通／困难 + 不同 XP”，否则用户仍不知道为什么选它。用户可调整时间，但顾问应相应改验收，不能把 45 分钟任务压到 15 分钟而假装完整目标还成立。[B3：弹性挑战][P4]

### 有意义的选择：不把最高 XP 做成唯一最优策略

选择应包含真实成本：深入一段实验可能意味着缩短另一项活动；先补基线可能让短期产出慢，却使后续判断可靠；恢复可能帮助维持长期路线。把这些取舍解释清楚，才符合 Schell 的 meaningful choice。[B1：lens #32，PDF 184–185]

优先级可以是带理由的排序，不必伪造十几个小数位的“最佳人生安排”。有关键上下文未知时，提出采集一条信息的低成本任务，优于直接建议高难度行动。

### 运行中：专注与遇阻支持

执行只显示当前检查点、所需材料和一个轻量入口“遇到阻碍”；提示可分“给一个线索／一起分析／直接示范”。技术能力证据记录帮助程度，不能在 AI 全部代做后宣称用户已独立掌握。家庭活动无需要求用户边陪伴边记录，事后自愿补记即可。

当现实发生变化，顾问应区分：任务本身卡住、耗时超估、外部打断、身体／情绪限制。对应选项是改变方法、缩小验收、改期或恢复；在确认可见提案后更新安排，保留已完成检查点。

“当晚上临时需要照护，我先保存实验结果，把剩余比较放到明天第一个可用窗口”是有具体触发与备用行为的计划。不是简单提醒“保持自律”。[P5，设计采用经典原则，见获取范围]

### 结算：先确认价值，再给奖励，再建议下一步

一次完成反馈应依次回答：

1. **发生了什么：**完整／部分／恢复／改期／未记录；不要把未记录等同失败。
2. **留下了什么：**结果、作品、反思或自述记录，注明证据类型与帮助程度。
3. **顾问怎样判断：**哪些验收已满足、哪些仍待证据；不确定时允许用户更正。
4. **因此改变了什么：**行动 XP、能力证据、可比较的 gap、解锁条件分别展示。
5. **下一步：**一个最有价值的改进或明日实验，附理由与成本。

奖励动效围绕“证据归档 → 具体进步显现 → 任务线展开”进行，重点庆祝真实变化；减少动效模式使用静态反馈，所有状态通过文字可读。不要让每次勾选都播放大段仪式、打断专注，或用动画掩盖评估没有依据。[B1：lens #49／#57／#58][B3]

**日终评价不能只算勾选比例。** 顾问同时评估关键承诺的实际执行、真实产物、是否尊重约束、哪些计划假设被证伪。一个因为照护改了计划但保留关键证据的日子，可以是有效的一天；这不意味着所有没做的事都被强行解释为成长。

## 7. 成长总览：把榜样 gap 变成可解释的能力地图

### 参照的是可核查的具体成果，不是人物神话

用户选择榜样时，Jarvis 提取的是某个作品／行为／成绩中的相关维度，显示来源和适用条件；用户选择近期目标，远期榜样提供方向。已有研究中的 Gary／NHS、Kipchoge 的历史赛事记录、Karpathy 的 micrograd 都可继续作为**带出处的参照案例**，但其数据应沿用原研究的证据范围，不在本轮假装重新核实人物全貌。[既有：reference-benchmarks.md]

模块详情建议包含：

- **为什么相关：**这位人物的哪项具体能力符合用户价值与阶段。
- **我的基线：**可直接观察的指标、作品验收、日期及缺失。
- **参照目标与当前阶段：**同定义的差值，或满足／待证实的验收项。
- **瓶颈判断：**当前主要缺口及证据，不只是一个抽象弱项词。
- **下一次挑战：**要补哪个缺口、留下什么证据、需要多少时间。
- **已解锁和待解锁：**前置能力与替代路径；用户可请求重新评估。

### 三种 gap 必须分开

**同口径测量差值：**单位、距离／条件、日期一致才能比较。以“越低越好”的耗时为例，`remaining = max(0, current − target)`；以“越高越好”的可验证指标为例，`remaining = max(0, target − current)`。不存在可比基线时显示“待建立”，不输出零差距。适宜范围指标显示低于／位于／高于目标区间，不能单向鼓励越多越好。

**作品能力缺口：**一份 rubric 有哪些条件已验证、部分支持、未知。可以显示“本阶段 6 项验收中 3 项已验证”，不能翻译为“已经拥有某榜样 50% 能力”。条目难度未必等距，若采用权重，权重是版本化的产品／用户选择，而不是自然科学常数。

**关系与价值差距：**用可控行为的观察、关系叙述与自愿反馈描述。可以展示“约定的倾听机会是否落实、冲突后是否尝试修复”，不能给家庭和父亲人格做百分位打分。[既有：evidence-scoring.md]

### 量化最少需要四条轨道

| 轨道 | 衡量什么 | 更新依据 | 不能混成什么 |
| --- | --- | --- | --- |
| 行动 XP／角色进度 | 用户认可的承诺与投入 | 一次挑战的约定规则和有效行动记录 | 健康效果、能力或人生价值 |
| 能力里程碑 | 在具体条件下能完成／解释／迁移什么 | 相应 rubric 与个人证据 | 勾选数、阅读时长、模型本身更强 |
| 现实结果／状态 | 成绩、体感、活动记录、实际作品结果 | 同口径测量或注明的自述 | 对因果收益的精确承诺 |
| 证据充分程度 | 当前判断已知多少、缺什么 | 来源、直接性、适用性、时间与独立性 | 一个无来源的“AI 置信度 96%” |

每个能力节点可以有“未探索 → 已实践 → 有证据 → 待复核／可迁移”等描述。**已实践是行动状态，已验证是评估状态，不应由同一个 checkbox 自动完成两个跃迁。** 行为记录不会因为中断归零；某项近期能力是否仍稳定则可标“需要复测”，不要用扣历史 XP 代替真实评估。

## 8. 最小可解释评分与评估规则

### 行动奖励：合约预算与证据幂等

每项挑战先约定一个有限奖励预算，并给检查点明确份额。拆成十个子任务仍共享父任务预算；同一份证据重复提交不重复发奖。部分完成认可已满足的检查点，其他份额保留或取消，以最终合约为准。调整计划不能通过反复“改期成功”无限产出奖励。

可实现的设计形式是 `earned = sum(已确认检查点的奖励份额)`，且不超过该合约预算。份额是产品选择，不是能力增量；纯时长活动可以按已记录时长，但不能把时长比例当作品质量比例。原型里的 XP 和阈值应标“演示规则”。

### 能力评估：按标准给结论，不给模型一个自由打分框

每个验收项留存：条件、用户证据、帮助程度、直接支持／反证／未知、结论理由、规则版本与评估日期。AI 只能在证据支持范围内更新；证据冲突显示冲突，保留原记录，允许补充、申诉或重测。

一个最小的示范结论：

> 已验证：固定条件下的评测可运行（日志 E21）。部分支持：能定位工具错误（解释有一个反例未覆盖）。待证实：改进能够迁移（尚无新案例）。下一步建议：用一个未见案例验证解释。此次行动记入角色 XP，迁移节点保持待证实。

对没有领域验证的自建 rubric，明确叫“当前阶段验收清单”；不要叫临床量表、专家认证或科学能力百分比。专业顾问可以提出深度意见，确定性仍须受证据约束。

### 排程评价：原计划与最终承诺并存

保留原计划和调整后的计划。最终完成度相对于**最终确认的承诺**计算，并同时显示原计划的变化；这样既不把合理改道当失败，也不通过删除未完成任务伪造完美日。对部分任务用检查点覆盖，缺失记录独立计数；日终可以显示“3 项有效推进、1 项改期、1 项待记录”。

建议的评估维度是：

- **可行性：**时间窗、固定承诺、必要材料与本人状态是否支持计划。
- **方向性：**关键任务是否对应选定目标与当前主要 gap。
- **执行／产物：**按约定完成什么，记录是否足以判断。
- **适应性：**计划与现实偏差怎样被处理，下次应改哪条假设。

它们可以各有可观察摘要，不必再合成一个“今日人生分”。如果当前 UI 保留 0–100 展示，就明确是某模块的**演示阶段指数**，附清单定义与来源，不能让用户误认科学评分。

## 9. 如何验证游戏化实际有效

原型首先验证完整因果链是否存在，不只验证按钮可点击：

| 流程 | 必须观察到的结果 |
| --- | --- |
| 修改一个关键个人约束 | 推荐档位／时间／验收实际变化，理由指出该约束 |
| 选择一个榜样维度 | 创建明确 gap 与阶段目标，任务能回链到这个维度 |
| 完成最低检查点 | 证据保留、有限行动奖励；不自动获得全部能力 |
| 重复提交／重评 | 奖励不重复，评估变化有原因与版本 |
| 临时照护／恢复／改期 | 不归零、不伪造完成；看得见计划差异，能再继续 |
| 挑战完成、证据充分 | 对应能力条件更新，下一项挑战实际可选 |
| 证据不足／不一致 | 显示待证实／冲突，不给自信的确定判定 |
| 桌面／移动／键盘／减少动效 | 所有核心操作可用，反馈无需仅靠动画、声音和颜色 |

真人试用应分别问：“这次建议是否真的理解你的背景”“奖励是否鼓励你本来想做的事情”“你是否愿意在困难日回来”“记录成本是否干扰现实行动”“有没有为了分数改变成不合适的行为”。不要仅以留在应用的时间或开屏次数衡量成功。

长期效果需观察任务产物、能力复测、恢复后的回归、计划估计的改善，并记录新鲜感消退后的体验。对单人使用可以做连续的个人观察与版本对照，但不要从相关趋势宣称机制造成了改善。真正的产品价值是帮助现实生活，而不是让用户持续在仪表盘上操作。[P6][B3：玩家悔恨感]

## 10. 本轮可实现的深度与后续边界

本轮原型最值得实现的是：**个人上下文卡 → 有理由的顾问判断 → 可选挑战合约 → 检查点与证据收据 → 单独的行动／能力结算 → 回到榜样 gap 与下一步。** 两个页面共用这条循环，展示技术、健康与家庭顾问如何因个人状态不同而作出不同建议。无需增加多种货币、抽奖、排行榜、装扮商店或复杂经济引擎。

可以让地图、称号、章节、反馈与解锁具有较强的游戏审美，但它们必须对应机制的真实事件。用户明确希望足够深的游戏化，因此不能只美化卡片、增添 badge 后结束；深度应来自长期路线、真实取舍、失败后的再策略、循序渐进的挑战与有证据的能力提升。[B1–B4]

真实 AI／个人数据／领域评估尚未接入时，UI 应就近注明演示；规则模拟可以充分测试交互与数据联动，但不能冒充已经读取个人历史或运行专业模型。后续引入真实 AI 时，优先验证证据读取、上下文更新、建议可追溯、评价可纠正与跨领域协调；不以多 Agent 数量替代专业效果。
